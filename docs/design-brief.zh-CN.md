# msgloom 设计概要

**状态：** 待审阅草稿

**设计规则：** [设计原则](design-principles.zh-CN.md)

## 1. 目的

msgloom 是一个个人工作信息系统。它帮助用户跟进重要工作。第一个目标是不遗漏任何需要用户回应的工作；第二个目标是减少跟进所需的阅读量。

系统面向每天来自多个信息源的数千条消息。每天有几十件工作事项需要用户本人回应，例如回复、审批或拒绝。每件事项可能横跨多个信息源的几十条消息，遗漏一件是不可接受的。

系统的主要产出是按主题组织的报告，而不是消息摘要列表。

## 2. 范围与边界

最终产品服务于单个用户。Outlook 邮件，以及 Microsoft Teams 的一对一聊天、群聊和频道，只是最初的信息源。产品必须允许随时间增加更多信息源，而不改变其目的。

msgloom 为用户的工作系统和日常 AI 使用提供辅助。它不替代这些系统，也不代表用户做出不受限制的决策。

## 3. 核心概念

以下术语在整个设计中具有相同含义。

| 术语 | 含义 |
| --- | --- |
| **信息源** | 提供信息的工作系统。 |
| **主题** | 由一个或多个信息源中的信息描述的工作事项。 |
| **分流规则** | 用户定义的标准，用于判断哪些事项需要关注及其优先级。 |
| **工作上下文** | 用户当前的工作情况，包括正在进行的项目、职责和未解决的问题。 |
| **用户偏好** | 用户提供的偏好和本地要求，例如组织内部标准或输出偏好，供 msgloom 在分流、分析和报告中统一应用。 |

## 4. 产品功能

**个人优先级。** 使用分流规则和工作上下文，识别需要关注的主题，并对规则未覆盖的主题提出优先级建议。用户的分流规则始终是决定性标准。

**主题分析。** 结合跨信息源的相关信息和用户的本地要求，说明进展及其影响。当进一步分析有帮助时，调查历史记录、附件和其他工作信息。

**定期报告。** 按用户为不同优先级定义的计划自动提供报告。

**行动支持。** 建议后续步骤，准备回复、任务和工单，并执行已获批准的业务行动。

**用户定制。** 接收用户的偏好和本地要求，并在分流、分析和报告中应用。

## 5. 报告契约

每份报告提供概览和主题详情。概览涵盖所有到期应报告的主题，包括关键进展、所需行动、截止时间和风险。

主题详情解释评估结果，并提供支持信息和指向信息源的引用。详情包含指向该主题每一条源消息的引用，包括乱序到达的回复，以及两人同时回复造成的会话分叉。明确标识缺失的信息和不确定的结论。

报告把每个主题及其证据完整、清楚地呈现出来。它提供摘要和指向原始消息的链接，用户在需要时可以阅读任何一条原始消息，例如在批准或拒绝一项请求之前。

报告通过邮件和本地网站提供，使用户能够从概览进入决策所需的详细信息。

## 6. 成功标准

成功意味着不遗漏任何需要用户回应的工作，并且用户能以更少的阅读量跟进重要工作。评判时首先看遗漏了多少这类工作或会改变决定的证据，其次看对重要信息的理解程度。两者都以用户审核过的示例为基准来衡量。处理的消息数量不是成功的衡量标准。

本概要定义最终产品。阶段范围和验收标准另行定义。
