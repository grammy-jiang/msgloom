### Telemetry results (item d)

The socket event hook sees `socket.connect`, `socket.getaddrinfo`,
`socket.gethostbyname` and `socket.sendto` on every path, including
`_socket`. It records the call and raises `OSError`. No packet leaves.

| Probe mode | Setting | Socket attempts | Role |
| --- | --- | --- | --- |
| `plain_run` | opt-out variables set | 0 | Planned path |
| `hooks_default` | none | 0 (plugin registered: `kedro-telemetry`) | Positive control: the plugin is present by default |
| `hooks_disabled` | disable tuple | 0 (plugins registered: none) | Control |
| `telemetry_hook` | none | 1 (`getaddrinfo`) | Positive control: the recorder sees the lookup |
| `telemetry_hook` | `DO_NOT_TRACK=1` | 0 | Control |
| `telemetry_hook` | `KEDRO_DISABLE_TELEMETRY=1` | 0 | Control. F0 read this variable in source only |
| `telemetry_hook` | both variables | 0 | Control |

Limits:

- The probe runs the telemetry hook directly. It does not start
  `KedroSession`. F0-04 covered sessions in a network namespace.
- The socket event hook sees Python-level socket calls only. A C extension that
  opens a socket without the Python socket module is not seen. No such
  extension is known in the Kedro set. This was not proven.
- The plugin is still installed and still importable. The control is the
  rule "no session, no hook entry points", which the source scan enforces by
  flagging `kedro.framework.session`, `kedro.framework.hooks.manager` and
  the entry-point groups.

### Log content (item e)

- Kedro prints Rich log lines to stdout on import. The probe captures them.
- With `sanitized_node`, the exception text is `node parse_node failed: code
  b6276ba7`. The code is a hash of the exception type name. It carries no
  input text.
- The scan has three known limits. It finds patterns, not meaning. It cannot
  detect free text that has no pattern. It needs a real-data corpus before it
  is a release gate.

## Twisted advisory reachability

Scope: Scrapy 2.19.0 and Twisted 26.4.0 from the project `.venv`, read only
(`python -B`). Package paths below are relative to its `site-packages`.
Advisory facts come from OSV records fetched on 2026-10-24. Each record
lists the fix as `26.10.0rc1`, a prerelease, except GHSA-8pqf-f4m5-798g,
which lists no fix.

Authority used:

- Scrapy 2.19 docs: `https://docs.scrapy.org/en/2.19/topics/telnetconsole.html`
  (the console listens on a TCP port and `TELNETCONSOLE_ENABLED` disables
  it) and `.../topics/settings.html`.
- Twisted 26.4.0 API docs: `https://docs.twisted.org/en/twisted-26.4.0/api/`
  pages for `twisted.mail.imap4.IMAP4Server` ("Protocol implementation for an
  IMAP4rev1 server"), `twisted.words.protocols.irc.IRC` ("Internet Relay Chat
  server protocol"), `twisted.web.http.HTTPChannel` ("A receiver for HTTP
  requests") and `twisted.web._newclient.HTTPClientParser` ("only handles HTTP
  responses").
- The installed source files listed in the table.

Method:

1. Find the vulnerable class and line in the installed source.
2. Find every import of that module in Scrapy and msgloom.
3. Run a real Scrapy crawl with `message_ingest.settings` (without the Graph
   add-on) against a loopback server. Record `Port.startListening` calls,
   `HTTPChannel` instances and imported modules. Command:
   `PYTHONPATH=. .venv/bin/python -B scripts/research/a2_f0_twisted_probe.py`.
4. Repeat with `--telnet` as a positive control.

Probe result without `--telnet` (exit 0): crawl status 200, `listen: []`,
`http_channels: 0`, `TELNETCONSOLE_ENABLED` false. Imported modules:
`twisted.conch.telnet` true, `twisted.web.http` true, `twisted.mail.imap4`
false, `twisted.words.protocols.irc` false, `twisted.words.xish.domish`
false, `twisted.web.server` false.

Probe result with `--telnet` (exit 0): `listen` has one entry on
`127.0.0.1`. The probe sees a listener when one exists.
