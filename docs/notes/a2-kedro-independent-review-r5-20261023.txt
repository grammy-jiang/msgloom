## P1 blocking findings

**P1-1. Contradictory SourceReferenceError mapping.**
- corrections:66, 72-81, impl C0.13 (`:138`) and handoff:101-108 say all escaped `SourceReferenceError` map to BLOCKED under one code. They say no subclass is needed and no exception-text parsing is allowed.
- design:223-234 (§9) says the translator must distinguish typed "catalog-identity/anchor/behind-cursor trust errors from ordinary missing evidence or malformed source associations", with only the former BLOCKED. It then says a "narrow typed subclass of SourceReferenceError at the existing accepted intake validation points… is a separately reviewed C0 task". It also forbids "treating every SourceReferenceError as an anchor mismatch".
- design:13-22 repeats the "distinguish" framing.
- These are incompatible rules, and the subclass would edit `intake.py`, which design §3 and the ADR treat as frozen. A coder cannot tell whether to add a subclass or map everything to one code.
- Source evidence for the conservative approach:
  - Escaping plain `SourceReferenceError` sites in `intake.py` are `:105`, `:116`, `:119`, `:253`, `:264`, `:323` and `:325`.
  - Sites at `:189` and `:412` are caught at `:190` and become held `materialization_failed`, so they never escape.
  - `ClaimUnavailableError` (`errors.py:24`) and `StaleClaimError` (`errors.py:28`) are separate classes.
  - The pin mismatch is a wrapper-owned `ValueError` (`scheduled.py:76`), so it can be a preflight.
  - So the single-code wrapper is implementable without touching intake.
- Fix: rewrite design §9 and the lines 13-22 header to match the corrections note. State that a subclass is not required, and either delete the subclass sentence or mark it a separate future refinement.
- Also state that escaped `:253`, `:264`, `:323` and `:325` (invariant failures) are intentionally BLOCKED. Row 68 of the table says invariant failure maps to FAILED, which overlaps.

## P2 recommendations

1. **Output-digest conflict.**
   - The conflict outcome is not in the status table.
   - A nondeterministic parser would conflict on every automatic retry and spin.
   - Assign it a terminal code, either FAILED `scheduled-persistence-failed` with no automatic retry or an A2-held reason.
2. **Reader errors during Kedro processing.**
   - State that the dataset adapter must catch `SourceReaderError`, including `SourceReferenceError`, from `read_entry`. It should turn these into `a2_input_disposition@1` (`source_evidence_unavailable`), not let them escape as BLOCKED.
   - Only errors escaping from intake or the preflight should map to `source-reference-invalid`. Corrections:66 says "from accepted intake/reader", which is ambiguous.
3. **Intake-held coverage in the receipt.**
   - Legacy `validate_completion` accepts a held-only workset with no frozen selections (`:252`, `:331`). `completion_receipts` skips the status check when no proofs exist (`:183`).
   - Corrections:201-203 requires INCOMPLETE for held entries, but the §5 receipt bullet and design:183-189 don't list it.
   - Make the rule part of the `a2_completion_receipt@2` contract: if `workset.held` is non-empty, the receipt requires INCOMPLETE.
4. **Scope-status "blocking code" source.**
   - Nothing in master persists BLOCKED outcomes.
   - Say whether the read-only command recomputes the anchor and pin checks or reads a new record. A new record would no longer be read-only.
5. **Replay target.**
   - Corrections:211-217 allows "original workset (or derived workset)". C0.14 should choose one, because the store has a single terminal finalization per workset.
6. **Mid-pending upgrade (item 6).**
   - Name the migration mechanism for AUTO-25.
   - Drain-before-cutover on the old engine is consistent with "one production path". "Approved versioned migration" is not defined.
7. **Doc cleanup.**
